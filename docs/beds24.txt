## 1. DATABASE SCHEMA

### Tables

#### beds24_credentials
**Location:** `supabase/migrations/20251020_add_beds24_channel_integration.sql`
**Purpose:** Store Beds24 OAuth credentials per location (property)
**Columns:**
- `id` (UUID, primary key)
- `tenant_id` (UUID, FK to tenants)
- `location_id` (UUID, FK to locations) - Added in migration 20251020_update_beds24_credentials_add_location_id.sql
- `refresh_token` (TEXT) - Long-lived OAuth token
- `access_token` (TEXT) - Short-lived API token
- `token_expires_at` (TIMESTAMPTZ)
- `is_active` (BOOLEAN)
- `sync_status` (TEXT)
- `last_synced_at` (TIMESTAMPTZ)
- `created_at`, `updated_at`, `created_by`, `updated_by`

**Constraints:**
- `unique_tenant_location_beds24` - One Beds24 connection per location
- RLS policies for tenant isolation

**Indexes:**
- `idx_beds24_credentials_tenant_location` - Query by tenant and location
- `idx_beds24_credentials_active` - Filter active credentials
- `idx_beds24_credentials_sync_status` - Track sync status

**RLS Policies:**
- Tenants can view own Beds24 credentials
- Tenants can insert own Beds24 credentials
- Tenants can update own Beds24 credentials
- Tenants can delete own Beds24 credentials

## 2. EDGE FUNCTIONS (Supabase Functions)

### beds24-token-exchange
**Path:** `supabase/functions/beds24-token-exchange/index.ts`
**Purpose:** Exchange Beds24 invite code for OAuth refresh token
**Method:** POST
**Authentication:** Requires user auth token
**Request Body:**
```typescript
{
  inviteCode: string,
  locationId: string,
  tenantId: string
}
```
**Flow:**
1. Receives invite code from Beds24 setup
2. Calls Beds24 API `/authentication/setup` with code header
3. Gets refresh_token and access_token
4. Stores in beds24_credentials table
5. Links to specific location

**API Endpoint:** `https://beds24.com/api/v2/authentication/setup`

### fetch-beds24-bookings
**Path:** `supabase/functions/fetch-beds24-bookings/index.ts`
**Purpose:** Fetch bookings from Beds24 and sync to external_bookings table
**Method:** POST
**Lines:** 602 total
**Key Features:**
- Token refresh management (refreshAccessToken function)
- Supports multiple properties via property mappings
- Maps Beds24 booking fields to CheckingCheckout format
- Handles currency conversion
- Source mapping (apiSourceId: 1=direct, 2=airbnb, 3=booking.com)
- Room mapping via beds24_property_mappings

**API Endpoint:** `https://beds24.com/api/v2/bookings`

**Token Management:**
- Uses refresh token to get access token
- Caches access token with expiry
- Auto-refreshes when expired

### sync-reservation-to-beds24
**Path:** `supabase/functions/sync-reservation-to-beds24/index.ts`
**Purpose:** Push direct CheckingCheckout reservations TO Beds24 (bi-directional sync)
**Method:** POST
**Lines:** 453 total
**Request Body:**
```typescript
{
  reservation_id: string,
  force?: boolean  // Force resync even if already synced
}
```

**Flow:**
1. Fetch reservation with room and location data
2. Check if already synced (skip if synced unless force=true)
3. Map CheckingCheckout room to Beds24 roomId
4. Create Beds24 booking payload
5. POST to Beds24 API `/bookings`
6. Update reservation with beds24_booking_id and sync status
7. Beds24 propagates to all channels automatically

**Beds24 Payload:**
```typescript
{
  roomId: number,
  status: "confirmed" | "request" | "cancelled",
  arrival: "YYYY-MM-DD",
  departure: "YYYY-MM-DD",
  numAdult: number,
  numChild: number,
  firstName?: string,
  lastName?: string,
  email?: string,
  mobile?: string,
  apiReference: string,  // Our reservation ID
  comment?: string
}
```

**API Endpoint:** `https://api.beds24.com/v2/bookings`

### setup-beds24-integration
**Path:** `supabase/functions/setup-beds24-integration/`
**Purpose:** Initial Beds24 setup and configuration

### beds24-booking-webhook
**Path:** `supabase/functions/beds24-booking-webhook/`
**Purpose:** Handle incoming webhooks from Beds24 for booking updates

### fetch-beds24-rooms
**Path:** `supabase/functions/fetch-beds24-rooms/`
**Purpose:** Fetch room list from Beds24 for room mapping configuration

## 7. INTEGRATION FLOW SUMMARY

### A. Initial Setup Flow
1. User navigates to Booking Channels Integration page
2. User generates invite code in Beds24 dashboard
3. User pastes invite code in CheckingCheckout
4. Frontend calls `beds24-token-exchange` Edge Function
5. Edge Function exchanges code for OAuth tokens
6. Tokens stored in `beds24_credentials` table (linked to location)
7. Success message displayed

### B. Property Mapping Flow
1. User configures property mappings (Beds24 property → CCO location)
2. Mappings stored in `beds24_property_mappings` table
3. Required for sync to work

### C. Room Mapping Flow
1. User clicks "Fetch Rooms" in Room Mappings tab
2. Frontend calls `fetch-beds24-rooms` Edge Function
3. Edge Function fetches rooms from Beds24 API
4. User maps Beds24 rooms to CheckingCheckout rooms
5. Mappings saved to `channel_room_mappings` table (channel='beds24')

### D. Incoming Sync Flow (Beds24 → CheckingCheckout)
1. User triggers manual sync OR scheduled job runs
2. Frontend/Scheduler calls `fetch-beds24-bookings` Edge Function
3. Edge Function:
   - Refreshes access token if needed
   - Fetches bookings from Beds24 API for all mapped properties
   - Maps Beds24 fields to CheckingCheckout format
   - Looks up room mappings
   - Inserts/updates `external_bookings` table
4. Bookings appear on calendar with "B24" badge and purple color

### E. Outgoing Sync Flow (CheckingCheckout → Beds24)
1. User creates direct reservation in CheckingCheckout
2. After save, frontend calls `sync-reservation-to-beds24` Edge Function
3. Edge Function:
   - Fetches reservation details
   - Maps CCO room to Beds24 roomId
   - Creates Beds24 booking payload
   - POSTs to Beds24 API `/bookings`
   - Updates reservation with `beds24_booking_id` and sync status
4. Beds24 propagates booking to all connected channels
5. Dates blocked on Airbnb, Booking.com, etc. automatically

### F. Calendar Display Flow
1. User views calendar
2. Calendar fetches reservations and external_bookings
3. Filters applied based on source toggles (including Beds24)
4. Beds24 bookings rendered with purple color and "B24" badge
5. Unmapped bookings shown in separate row

## 8. API ENDPOINTS USED

### Beds24 API v2 Endpoints

1. **Authentication Setup**
   - URL: `https://beds24.com/api/v2/authentication/setup`
   - Method: GET
   - Headers: `{ code: inviteCode }`
   - Returns: `{ refreshToken, token, expiresIn }`

2. **Token Refresh**
   - URL: `https://beds24.com/api/v2/authentication/token`
   - Method: GET
   - Headers: `{ refreshToken }`
   - Returns: `{ token, expiresIn }`

3. **Fetch Bookings**
   - URL: `https://beds24.com/api/v2/bookings`
   - Method: GET
   - Headers: `{ token: accessToken }`
   - Query Params: `{ propertyId, from, to }`
   - Returns: Array of bookings

4. **Create Booking**
   - URL: `https://api.beds24.com/v2/bookings`
   - Method: POST
   - Headers: `{ token: accessToken, Content-Type: application/json }`
   - Body: Beds24BookingPayload
   - Returns: Created booking with ID

5. **Fetch Rooms**
   - URL: `https://beds24.com/api/v2/rooms` (inferred)
   - Method: GET
   - Headers: `{ token: accessToken }`
   - Returns: Array of rooms

## 10. KEY ISSUES & FIXES NEEDED

### Potential Issues to Investigate:

1. **Token Expiry Management**
   - Current implementation caches access token in Edge Function memory
   - May not handle concurrent requests well
   - Consider Redis or database-based token caching

2. **Room Mapping Validation**
   - No validation that Beds24 room exists before saving mapping
   - Could lead to sync failures

3. **Webhook Implementation**
   - beds24-booking-webhook function exists but integration unclear
   - Real-time sync may not be working

4. **Error Handling**
   - Sync failures update beds24_sync_error but no retry mechanism
   - Manual retry only via UI button

5. **Currency Handling**
   - Beds24 uses multiple currency fields (currency, ucurrency)
   - May have conversion issues (documented in BEDS24_CURRENCY_AND_SYNC_FIX.md)

6. **Date Blocking**
   - beds24_dates_blocked field exists but blocking logic unclear
   - May not be preventing double bookings effectively

7. **Multi-Property Support**
   - Property mappings support multiple properties
   - But UI may not handle multiple properties per tenant well

8. **Sync Schedule**
   - No visible scheduled sync job
   - Relies on manual sync trigger

9. **Bi-directional Sync Conflicts**
   - No conflict resolution if same room booked in both systems
   - Could lead to double bookings

10. **RLS Policy Completeness**
    - Fixed in 20251020155826 but needs audit
    - Ensure all queries properly filtered by tenant_id

## SUMMARY

The Beds24 integration is a **comprehensive, bi-directional channel manager integration** that:

1. **Connects** CheckingCheckout to Beds24 via OAuth
2. **Syncs** bookings FROM Beds24 to CheckingCheckout (display external bookings)
3. **Pushes** direct CheckingCheckout bookings TO Beds24 (close dates on all channels)
4. **Maps** rooms and properties between systems
5. **Displays** Beds24 bookings on calendar with visual indicators
6. **Tracks** sync status and handles errors

**Total Files Involved:** 40+ files across database, backend, frontend, and documentation
**Total Lines of Code:** 2000+ lines (estimated)
**Edge Functions:** 6 functions
**Database Tables:** 3 tables (beds24_credentials, beds24_property_mappings, plus reservation columns)
**Frontend Components:** 15+ components
**Documentation Files:** 14 files

**Critical Dependencies:**
- Beds24 API v2
- Supabase Edge Functions
- Row Level Security policies
- OAuth token management
- Room mapping configuration
