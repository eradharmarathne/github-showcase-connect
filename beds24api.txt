## AUTHENTICATION

### Token Exchange (Initial Setup)
**Endpoint:** `GET https://beds24.com/api/v2/authentication/setup`

Exchange invite code for refresh token (one-time setup).

**Headers:**
```
accept: application/json
code: {inviteCode}
```

**Response:**
```json
{
  "refreshToken": "long-lived-token",
  "token": "access-token",
  "expiresIn": 3600
}
```

### Token Refresh
**Endpoint:** `GET https://beds24.com/api/v2/authentication/token`

Refresh access token using refresh token.

**Headers:**
```
accept: application/json
refreshToken: {refreshToken}
```

**Response:**
```json
{
  "token": "new-access-token",
  "expiresIn": 3600
}
```

### Authentication for API Calls

**Security Schemes:**

1. **Token Header:**
   - Header: `token`
   - Value: Access token (short-lived, use refreshed token)

2. **Organization Header (for partners only):**
   - Header: `organization`
   - Value: Your organization name

**Example Request Headers:**
```
token: your-access-token-here
organization: YourOrgName  (only if integration partner)
```

## HEADERS & RATE LIMITING

### Response Headers

All API responses include rate limiting information:

**X-FiveMinCreditLimit:**
- Description: Maximum credits you can use in 5 minutes
- Type: Integer
- Example: 100

**X-FiveMinCreditLimit-ResetsIn:**
- Description: Seconds until credit limit resets
- Type: Integer
- Example: 100

**X-FiveMinCreditLimit-Remaining:**
- Description: Remaining credits for current 5-minute window
- Type: Integer
- Example: 85

**X-RequestCost:**
- Description: Credits consumed by this request
- Type: Integer
- Example: 1

### Pagination Parameter

**page:**
- Location: Query parameter
- Description: Get page beyond the first
- Type: Integer
- Example: `?page=2`

## BOOKINGS API

### GET /bookings

Get bookings matching specified criteria. By default, only upcoming bookings returned.

**Endpoint:** `GET /bookings`

**Query Parameters:**

| Parameter | Type | Description |
|-----------|------|-------------|
| `filter` | string | arrivals, departures, new, current |
| `propertyId` | integer[] | Multiple property IDs |
| `roomId` | integer[] | Multiple room IDs |
| `id` | integer[] | Booking IDs |
| `masterId` | integer[] | Master booking IDs |
| `apiReference` | string[] | API references |
| `channel` | string | Channel name (see channel enum) |
| `arrival` | date | YYYY-MM-DD |
| `arrivalFrom` | date | YYYY-MM-DD |
| `arrivalTo` | date | YYYY-MM-DD |
| `departure` | date | YYYY-MM-DD |
| `departureFrom` | date | YYYY-MM-DD |
| `departureTo` | date | YYYY-MM-DD |
| `bookingTimeFrom` | datetime | YYYY-MM-DDTHH:MM:SS (UTC) |
| `bookingTimeTo` | datetime | YYYY-MM-DDTHH:MM:SS (UTC) |
| `modifiedFrom` | datetime | YYYY-MM-DDTHH:MM:SS |
| `modifiedTo` | datetime | YYYY-MM-DDTHH:MM:SS |
| `searchString` | string | Guest name, email, apiref, bookingId |
| `includeInvoiceItems` | boolean | Include invoice items |
| `includeInfoItems` | boolean | Include info items |
| `includeGuests` | boolean | Include guest data (requires scope) |
| `includeBookingGroup` | boolean | Include booking group IDs |
| `status` | string[] | confirmed, request, new, cancelled, black, inquiry |
| `page` | integer | Page number |

**Filter Values:**
- `arrivals` - Bookings arriving today
- `departures` - Bookings departing today (confirmed, new, request)
- `new` - Bookings created in past 24 hours
- `current` - Bookings checked in (arrival ≤ today, departure ≥ today)

**Channel Enum:**
```
agoda, airbnb, asiatravel, atraveode, booking, bookingpage, despegar, 
direct, edreamsodigeo, expedia, feratel, goibibo, hometogo, hostelworld, 
hotelbeds, hrs, jomres, marriott, ostrovokru, ota, tiket, tomastravel, 
traveloka, travia, traum, trip, tripadvisorrentals, vacationstay, vrbo, 
airbnbical, bedandbreakfasteu, bedandbreakfastnl, bookeasycomau, 
bookitconz, flipkey, googlecal, googleads, guestlinkcouk, 
holidaylettingscouk, hostelinternational, hostelsclub, housetripcom, 
icalimport1, icalimport2, icalimport3, lastminute, nzaa, reserva, 
rezintelnet, tablethotels, traumferienwohnungen, trivagocom, 
visitscotlandcom, vrboical, webroomsconz
```

**Response:**
```json
{
  "success": true,
  "type": "booking",
  "pages": {
    "current": 1,
    "total": 5
  },
  "data": [
    {
      "id": 12345,
      "propertyId": 1001,
      "roomId": 322790,
      "status": "confirmed",
      "arrival": "2021-01-01",
      "departure": "2021-01-05",
      "numAdult": 2,
      "numChild": 1,
      "firstName": "John",
      "lastName": "Doe",
      "email": "johndoe@example.com",
      "price": 500.00,
      "channel": "direct",
      "bookingTime": "2020-12-15T10:30:00Z",
      "modifiedTime": "2020-12-15T10:30:00Z"
    }
  ]
}
```

### POST /bookings

Create or update bookings. Can create multiple bookings in single request.

**Endpoint:** `POST /bookings`

**Request Body:**
```json
[
  {
    "roomId": 1234567,
    "status": "confirmed",
    "arrival": "2021-01-01",
    "departure": "2021-01-05",
    "numAdult": 2,
    "numChild": 1,
    "title": "Mr",
    "firstName": "John",
    "lastName": "Doe",
    "email": "johndoe@example.com",
    "mobile": "123456789",
    "address": "123 Fake St",
    "city": "Melbourne",
    "state": "Victoria",
    "postcode": "3000",
    "country": "Australia",
    "comments": "Early check-in requested",
    "apiReference": "CCO-RES-001"
  }
]
```

**Update Existing Booking:**
```json
[
  {
    "id": 12345,
    "status": "cancelled",
    "departure": "2021-01-04"
  }
]
```

**Create Booking with Invoice Item:**
```json
[
  {
    "roomId": 322790,
    "arrival": "2022-06-29",
    "departure": "2022-07-09",
    "numAdult": 2,
    "invoiceItems": [
      {
        "type": "charge",
        "qty": 2,
        "amount": 50
      }
    ]
  }
]
```

**Required Fields for New Booking:**
- `roomId` (integer)
- `arrival` (date: YYYY-MM-DD)
- `departure` (date: YYYY-MM-DD)

**Optional Fields:**
- `masterId` - Master booking ID for grouping
- `unitId` - Specific unit ID
- `roomQty` - Number of rooms
- `status` - confirmed, request, new, cancelled, black, inquiry
- `numAdult` (0-99)
- `numChild` (0-99)
- `title`, `firstName`, `lastName` (max 100 chars)
- `email` (max 100 chars)
- `phone`, `mobile`, `fax` (max 100 chars)
- `company` (max 100 chars)
- `address` (max 250 chars)
- `city`, `state`, `postcode` (max 100 chars)
- `country` - Free text (max 100)
- `country2` - 2-letter code (e.g., "DE")
- `arrivalTime` (max 100 chars)
- `voucher` (max 100 chars)
- `comments` (max 1000 chars)
- `notes` (max 2000 chars)
- `message` (max 1000 chars)
- `groupNote` (max 5000 chars)
- `custom1` - `custom10` (max 1000 chars each)
- `flagColor` - 6-char hex color (e.g., "FF0000")
- `flagText` (max 32 chars)
- `lang` - 2-char code (e.g., "en")
- `price` (0 - 99999999.99)
- `deposit` (0 - 99999999.99)

**Response:**
```json
[
  {
    "success": true,
    "id": 12345,
    "message": "Booking created successfully"
  }
]
```

## INVENTORY API

### GET /inventory/rooms/availability

Get availability status for rooms on specified dates.

**Endpoint:** `GET /inventory/rooms/availability`

**Query Parameters:**

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `roomId` | integer[] | No | Room IDs |
| `propertyId` | integer[] | No | Property IDs |
| `startDate` | date | Yes | YYYY-MM-DD |
| `endDate` | date | Yes | YYYY-MM-DD (last bookable night) |
| `page` | integer | No | Page number |

**Response:**
```json
{
  "success": true,
  "type": "availability",
  "pages": {
    "current": 1,
    "total": 1
  },
  "data": [
    {
      "roomId": 322790,
      "date": "2021-01-01",
      "numAvail": 5,
      "status": "available"
    }
  ]
}
```

### GET /inventory/rooms/calendar

Get per-day calendar values (availability, pricing, restrictions).

**Endpoint:** `GET /inventory/rooms/calendar`

**Query Parameters:**

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `startDate` | date | Yes | YYYY-MM-DD |
| `endDate` | date | Yes | YYYY-MM-DD |
| `roomId` | integer[] | No | Room IDs |
| `propertyId` | integer[] | No | Property IDs |
| `includeNumAvail` | boolean | No | Include availability count |
| `includeMinStay` | boolean | No | Include min stay |
| `includeMaxStay` | boolean | No | Include max stay |
| `includeMultiplier` | boolean | No | Include price multiplier |
| `includeOverride` | boolean | No | Include override status |
| `includePrices` | boolean | No | Include all 16 price tiers |
| `includeChannels` | boolean | No | Include channel limits |

**Response:**
```json
{
  "success": true,
  "type": "calendar",
  "data": [
    {
      "roomId": 322790,
      "calendar": [
        {
          "from": "2021-01-01",
          "to": "2021-01-05",
          "numAvail": 5,
          "minStay": 2,
          "maxStay": 14,
          "multiplier": 1.2,
          "override": "none",
          "price1": 100.00,
          "channels": {
            "airbnb": {
              "maxBookings": 2
            }
          }
        }
      ]
    }
  ]
}
```

**Calendar Override Enum:**
- `none` - No restriction
- `blackout` - Blocked dates
- `exception` - Exception period
- `noCheckIn` - No check-in allowed
- `noCheckOut` - No check-out allowed
- `noCheckInOrCheckOut` - No check-in or check-out

**Calendar Fields:**
- `from`, `to` - Date range (YYYY-MM-DD)
- `numAvail` - Available units (can be negative if overbooked)
- `minStay` - Minimum nights (1-365)
- `maxStay` - Maximum nights (1-364)
- `multiplier` - Price multiplier (0.1-100, default: 1)
- `override` - Restriction enum
- `price1` through `price16` - Rate plan prices
- `channels` - Per-channel max bookings (agoda, airbnb, etc.)

## MESSAGES API

### GET /bookings/messages

Get messages for bookings.

**Endpoint:** `GET /bookings/messages`

**Query Parameters:**

| Parameter | Type | Description |
|-----------|------|-------------|
| `id` | integer[] | Message IDs |
| `propertyId` | integer[] | Property IDs |
| `roomId` | integer[] | Room IDs |
| `bookingId` | integer[] | Booking IDs |
| `masterId` | integer[] | Master booking IDs |
| `filter` | string | read, unread |
| `maxAge` | integer | Max age in days (1-999) |
| `source` | string | host, guest, internalNote, system |
| `page` | integer | Page number |

**Response:**
```json
{
  "success": true,
  "type": "message",
  "data": [
    {
      "id": 8001,
      "bookingId": 12345,
      "source": "guest",
      "message": "Can we check in early?",
      "time": "2021-01-01T10:30:00Z",
      "read": false
    }
  ]
}
```

### POST /bookings/messages

Send messages or mark as read.

**Request Body (Send Message):**
```json
[
  {
    "bookingId": 12345,
    "source": "host",
    "message": "Yes, early check-in is available.",
    "attachment": "base64-encoded-file",
    "attachmentName": "floor-plan.pdf",
    "attachmentMimeType": "application/pdf"
  }
]
```

**Supported Attachment MIME Types:**
- Airbnb: `image/jpeg`, `image/png`, `image/gif`
- Booking.com: `image/jpeg`, `image/png`
- VRBO: `image/jpeg`, `image/png`, `image/gif`, `application/pdf`

**Request Body (Mark as Read):**
```json
[
  {
    "id": 8001,
    "read": true
  }
]
```

### PATCH /bookings/messages

Make bulk changes to messages.

**Request Body:**
```json
{
  "bookingId": [12345, 12346],
  "markAsRead": true
}
```

## IMPORTANT NOTES

### Date Formats
- **Dates:** YYYY-MM-DD (e.g., "2021-01-05")
- **Datetimes:** YYYY-MM-DDTHH:MM:SS (e.g., "2021-01-05T14:30:00")
- **UTC for bookingTime:** Times in UTC timezone

### Timezones
- All dates are in property's timezone
- bookingTime and modifiedTime are in UTC

### Pagination
- Use `page` parameter to navigate results
- Response includes `pages.current` and `pages.total`
- Default page size varies by endpoint

### Rate Limiting
- Credit-based system (5-minute windows)
- Monitor X-FiveMinCreditLimit headers
- Implement exponential backoff on limit reached

### Error Handling
- 200: Success
- 400: Bad request (check error message)
- 401: Unauthorized (check token)
- 429: Rate limit exceeded
- 500: Server error

**Error Response:**
```json
{
  "success": false,
  "error": "Error description",
  "field": "fieldName",
  "message": "Detailed error message"
}
```

### Best Practices

1. **Token Management:**
   - Store refresh token securely
   - Refresh access token before expiry
   - Cache access token with expiry timestamp

2. **Rate Limiting:**
   - Monitor credit headers
   - Implement request queuing
   - Batch operations when possible

3. **Booking Creation:**
   - Always include `apiReference` for tracking
   - Validate dates before sending
   - Check room availability first

4. **Data Sync:**
   - Use `modifiedFrom` to get updates
   - Poll regularly for new bookings
   - Implement webhook for real-time updates

5. **Error Recovery:**
   - Retry failed requests with exponential backoff
   - Log all API interactions
   - Validate data before sending
