## AUTHENTICATION

### Overview
Beds24 API V2 uses token-based authentication with two token types:

**1. Long-life Tokens**
- Read-only access
- Do not expire if used within **90 days**
- Ideal for integrations that only need to read data

**2. Refresh Tokens**
- Generate short-lived access tokens (24 hours)
- Do not expire if used within **30 days**
- Can read and make changes

### Authentication Flow

#### Step 1: Generate Invite Code
Go to: https://beds24.com/control3.php?pagetype=apiv2

Settings to configure:
- **Scopes:** Select permissions (read, write, delete)
- **Linked Properties:** Allow/deny access to properties linked to your account
- **IP Whitelisting:** Optional (comma-separated IPs: `192.168.0.1, 127.0.0.1`)
- **Expiration:** Invite codes expire after **24 hours**

#### Step 2: Exchange Invite Code for Refresh Token
**Endpoint:** `GET /authentication/setup`

**Headers:**
```http
accept: application/json
code: {inviteCode}
```

**Response:**
```json
{
  "refreshToken": "Ea6DftE50aYYRe/qAd9SkQaSmTF6kaLQxH6gtRxO1h10yVC64d4qIj4BGiQOU+y5",
  "token": "wEoJHQIwRrLwHqTqAsn0/XjzaZkVk4E8sSDwbRN2HKDlulkt6n7aHQCcvdqfX+y5",
  "expiresIn": 3600
}
```

**IMPORTANT:** Store `refreshToken` securely. You'll need it to generate new access tokens.

#### Step 3: Refresh Access Token (Every 24 Hours)
**Endpoint:** `GET /authentication/token`

**Headers:**
```http
accept: application/json
refreshToken: {refreshToken}
```

**Response:**
```json
{
  "token": "wEoJHQIwRrLwHqTqAsn0/XjzaZkVk4E8sSDwbRN2HKDlulkt6n7aHQCcvdqfX+y5",
  "expiresIn": 3600
}
```

**Token Details:**
- Expires: 24 hours after generation
- Length: 152-172 characters
- Refresh before expiry to avoid interruption

#### Step 4: Use Token in API Requests

**Required Header:**
```http
token: {access-token}
```

**Optional Header (integration partners only):**
```http
organization: YourOrgName
```

**Example cURL:**
```bash
curl -X 'GET' \
  'https://api.beds24.com/v2/bookings?arrival=2025-11-01&arrivalTo=2025-11-30' \
  -H 'accept: application/json' \
  -H 'token: wEoJHQIwRrLwHqTqAsn0/XjzaZkVk4E8sSDwbRN2HKDlulkt6n7aHQCcvdqfX+y5'
```

## SCOPES & PERMISSIONS

Scopes determine what your token can access. Set when creating invite code.

### Available Scopes

#### Bookings
- `read:bookings` - Basic booking info (dates, status, room)
- `write:bookings` - Create/update bookings
- `delete:bookings` - Delete bookings
- `all:bookings` - All booking operations

#### Bookings - Personal Data
- `read:bookings-personal` - Guest info (name, email, phone, address)
- Requires `read:bookings` scope as well

#### Bookings - Financial Data
- `read:bookings-financial` - Invoice, payments, charges
- Requires `read:bookings` scope as well

#### Inventory
- `read:inventory` - Availability, calendar, offers
- `write:inventory` - Update calendar, prices, restrictions

#### Properties
- `read:properties` - Property and room configuration
- `write:properties` - Create/update properties and rooms

#### Accounts
- `read:accounts` - Account information
- `write:accounts` - Update account settings

### Scope Methods
- `read:` - GET endpoints only
- `write:` - POST/PATCH endpoints (create/update)
- `delete:` - DELETE endpoints
- `all:` - Shortcut for read+write+delete

### Linked Properties
By default, tokens **cannot** access linked properties. Enable this when creating invite code.

**How to link properties:** Account Management > Manage Account > Manage Property

## RATE LIMITING & HEADERS

### API Credit System
- **Window:** 5 minutes (rolling)
- **Scope:** Account level (all tokens share the same limit)
- **Cost:** Dynamic (varies by request complexity)
- **Limit:** Varies by account type

### Rate Limit Headers (Every Response)

**X-FiveMinCreditLimit**
- Max credits available in 5-minute window
- Example: `100`

**X-FiveMinCreditLimit-Remaining**
- Credits remaining in current window
- Example: `85`

**X-FiveMinCreditLimit-ResetsIn**
- Seconds until window resets
- Example: `280`

**X-RequestCost**
- Credits consumed by this request
- Example: `1`

**Monitoring:**
```javascript
if (response.headers['X-FiveMinCreditLimit-Remaining'] < 10) {
  // Slow down or wait until reset
  const resetIn = response.headers['X-FiveMinCreditLimit-ResetsIn'];
  console.warn(`Low credits. Resets in ${resetIn}s`);
}
```

### Request Limits
- **Max POST payload size:** ~1MB
- **Max array items per POST:** 10,000 top-level items
- **Pagination:** Use `?page=2` for additional results

## POST REQUEST PATTERNS

**CRITICAL:** All POST endpoints accept **arrays**, not single objects.

### Creating vs Updating

**Create new item (no `id` field):**
```json
[
  {
    "roomId": 322790,
    "arrival": "2025-11-15",
    "departure": "2025-11-20",
    "firstName": "John",
    "lastName": "Doe"
  }
]
```

**Update existing item (include `id` field):**
```json
[
  {
    "id": 12345,
    "status": "confirmed",
    "departure": "2025-11-21"
  }
]
```

**Batch operations (create + update):**
```json
[
  {
    "roomId": 322790,
    "arrival": "2025-11-15",
    "departure": "2025-11-20"
  },
  {
    "id": 12345,
    "status": "cancelled"
  },
  {
    "id": 12346,
    "departure": "2025-11-22"
  }
]
```

### Subitems (Invoice Items, Info Items)

**Add new subitem:**
```json
[
  {
    "id": 12345,
    "invoiceItems": [
      {
        "type": "charge",
        "qty": 2,
        "amount": 50,
        "description": "Extra towels"
      }
    ]
  }
]
```

**Update existing subitem:**
```json
[
  {
    "id": 12345,
    "invoiceItems": [
      {
        "id": 2222222,
        "qty": 3,
        "amount": 60
      }
    ]
  }
]
```

**Delete subitem (include only `id`):**
```json
[
  {
    "id": 12345,
    "invoiceItems": [
      {
        "id": 2222222
      }
    ]
  }
]
```

### Response Structure

```json
[
  {
    "success": true,
    "new": {
      "bookingId": 12347,
      "invoiceItemId": 2222223
    },
    "modified": {
      "departure": "2025-11-21"
    },
    "errors": [],
    "warnings": [
      {
        "message": "Non-required field had invalid data"
      }
    ],
    "info": [
      {
        "message": "Booking created successfully"
      }
    ]
  }
]
```

**Response Array Order:** Matches request array order (1:1 correspondence)

**Success Field:**
- `true` - All operations succeeded
- `false` - One or more operations failed (check `errors` array)

**Note:** `success: false` doesn't mean nothing changed. E.g., booking created but invalid invoice item failed.

## BOOKINGS API

### GET /bookings

Get bookings matching criteria. **Default: only upcoming bookings.**

**Endpoint:** `GET /bookings`

**Query Parameters:**

| Parameter | Type | Description |
|-----------|------|-------------|
| `filter` | string | `arrivals`, `departures`, `new`, `current` |
| `propertyId` | integer[] | Multiple property IDs |
| `roomId` | integer[] | Multiple room IDs |
| `id` | integer[] | Specific booking IDs |
| `masterId` | integer[] | Master booking IDs (group bookings) |
| `apiReference` | string[] | Your custom reference codes |
| `channel` | string | Channel name (see channel enum below) |
| `arrival` | date | Exact arrival date (YYYY-MM-DD) |
| `arrivalFrom` | date | Arrival range start |
| `arrivalTo` | date | Arrival range end |
| `departure` | date | Exact departure date |
| `departureFrom` | date | Departure range start |
| `departureTo` | date | Departure range end |
| `bookingTimeFrom` | datetime | Booking created after (YYYY-MM-DDTHH:MM:SS UTC) |
| `bookingTimeTo` | datetime | Booking created before |
| `modifiedFrom` | datetime | Modified after |
| `modifiedTo` | datetime | Modified before |
| `searchString` | string | Guest name, email, apiRef, bookingId |
| `status` | string[] | `confirmed`, `request`, `new`, `cancelled`, `black`, `inquiry` |
| `includeInvoiceItems` | boolean | Include invoice line items |
| `includeInfoItems` | boolean | Include info items |
| `includeGuests` | boolean | Include guest data (requires scope) |
| `includeBookingGroup` | boolean | Include booking group IDs |
| `page` | integer | Page number (default: 1) |

**Filter Values:**
- `arrivals` - Bookings checking in today
- `departures` - Bookings checking out today (status: confirmed, new, request)
- `new` - Bookings created in past 24 hours
- `current` - Bookings currently checked in (arrival ≤ today ≤ departure)

**Channel Enum (partial list):**

[
  {
    "success": true,

### GET /bookings/messages

**Endpoint:** `GET /bookings/messages`

|-----------|------|-------------|

### POST /bookings/messages

Send messages or mark as read. **Only works for OTA bookings**, not direct bookings.

**Endpoint:** `POST /bookings/messages`

**Send Message:**
```json
[
  {
    "bookingId": 12345,
    "source": "host",
    "message": "Yes, early check-in is available at 12pm.",
    "attachment": "base64-encoded-file-data",
    "attachmentName": "floor-plan.pdf",
    "attachmentMimeType": "application/pdf"
  }
]
```

**Supported MIME Types:**
- Airbnb: `image/jpeg`, `image/png`, `image/gif`
- Booking.com: `image/jpeg`, `image/png`
- VRBO: `image/jpeg`, `image/png`, `image/gif`, `application/pdf`

**Mark as Read:**
```json
[
  {
    "id": 8001,
    "read": true
  }
]
```

### PATCH /bookings/messages

Bulk update messages.

**Endpoint:** `PATCH /bookings/messages`

**Request Body:**
```json
{
  "bookingId": [12345, 12346],
  "markAsRead": true
}
```

**IMPORTANT:** To update room-level settings, you **must** include the `property id`. Missing `id` may cause errors or silent failures.

**Create New Property:**
```json
[
  {
    "name": "New Beach Resort",
    "propertyType": "hotel",
    "currency": "USD",
    "address": "456 Ocean Ave",
    "city": "Miami",
    "state": "FL",
    "country": "United States",
    "country2": "US"
  }
]
```

**Update Property:**
```json
[
  {
    "id": 1001,
    "name": "Updated Hotel Name",
    "phone": "+1987654321"
  }
]
```

**Modify Price Rule Name:**
```json
[
  {
    "id": 1001,
    "roomTypes": [
      {
        "id": 322790,
        "priceRules": [
          {
            "priceruleid": 1,
            "name": "Winter Special Rate"
          }
        ]
      }
    ]
  }
]
```

**Note:** Cannot create new price rules via API, only modify existing ones.

| Parameter | Type | Required | Description |

| `roomId` | integer[] | No | Room IDs |
| `propertyId` | integer[] | No | Property IDs |
| `startDate` | date | Yes | YYYY-MM-DD |
| `endDate` | date | Yes | YYYY-MM-DD (last bookable night) |
| `page` | integer | No | Page number |

**Response:**
```json
{
  "success": true,
  "type": "availability",
  "pages": {
    "current": 1,
    "total": 1
  },
  "data": [
    {
      "roomId": 322790,
      "date": "2025-11-15",
      "numAvail": 5,
      "status": "available"
    },
    {
      "roomId": 322790,
      "date": "2025-11-16",
      "numAvail": 0,
      "status": "unavailable"
    }
  ]
}
```

**Interpreting Availability:**
- `status: "available"` - Check-in allowed on this date
- `status: "unavailable"` - Check-in NOT allowed
- If date is unavailable but **previous date** is available → Check-out is allowed

**Example:**
```json
{
  "2025-11-15": true,
  "2025-11-16": true,
  "2025-11-17": false
}
```
- Can check in: Nov 15, Nov 16
- Can check out: Nov 15, Nov 16, **Nov 17** (because Nov 16 is available)

### GET /inventory/rooms/calendar

Get per-day calendar values (prices, availability, restrictions).

**Endpoint:** `GET /inventory/rooms/calendar`

**Query Parameters:**

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `startDate` | date | Yes | YYYY-MM-DD |
| `endDate` | date | Yes | YYYY-MM-DD |
| `roomId` | integer[] | No | Room IDs |
| `propertyId` | integer[] | No | Property IDs |
| `includeNumAvail` | boolean | No | Include availability count |
| `includeMinStay` | boolean | No | Include min stay restriction |
| `includeMaxStay` | boolean | No | Include max stay restriction |
| `includeMultiplier` | boolean | No | Include price multiplier |
| `includeOverride` | boolean | No | Include override status |
| `includePrices` | boolean | No | Include all 16 price tiers |
| `includeChannels` | boolean | No | Include channel-specific limits |

**Response:**
```json
{
  "success": true,
  "type": "calendar",
  "data": [
    {
      "roomId": 322790,
      "calendar": [
        {
          "from": "2025-11-15",
          "to": "2025-11-20",
          "numAvail": 5,
          "minStay": 2,
          "maxStay": 14,
          "multiplier": 1.2,
          "override": "none",
          "price1": 100.00,
          "price2": 120.00,
          "channels": {
            "airbnb": {
              "maxBookings": 3
            },
            "booking": {
              "maxBookings": 2
            }
          }
        }
      ]
    }
  ]
}
```

**Calendar Fields:**
- `from`, `to` - Date range (YYYY-MM-DD)
- `numAvail` - Available units (can be negative if overbooked)
- `minStay` - Minimum nights (1-365)
- `maxStay` - Maximum nights (1-364)
- `multiplier` - Price multiplier (0.1-100, default: 1)
- `override` - Restriction type
- `price1` to `price16` - Rate plan prices
- `channels` - Per-channel max bookings

**Override Values:**
- `none` - No restriction
- `blackout` - Blocked dates (no bookings)
- `exception` - Exception period
- `noCheckIn` - No check-in allowed
- `noCheckOut` - No check-out allowed
- `noCheckInOrCheckOut` - Neither check-in nor check-out

## BEST PRACTICES

### Token Management
**Don't request new tokens for every API call.** Tokens last 24 hours.

**Bad:**
```javascript
// ❌ Wastes credits
async function getBookings() {
  const token = await refreshToken();
  return fetch('/bookings', { headers: { token } });
}
```

**Good:**
```javascript
// ✅ Reuse token, refresh when needed
let cachedToken = null;
let tokenExpiry = null;

async function getToken() {
  if (cachedToken && tokenExpiry > Date.now()) {
    return cachedToken;
  }
  const { token, expiresIn } = await refreshToken();
  cachedToken = token;
  tokenExpiry = Date.now() + (expiresIn - 300) * 1000; // 5min buffer
  return token;
}
```

### Use Webhooks Instead of Polling

**Bad:**
```javascript
// ❌ Poll every minute for new bookings
setInterval(async () => {
  const bookings = await getBookings({ filter: 'new' });
}, 60000);
```

**Good:**
```javascript
// ✅ Set up webhook to receive new bookings instantly
app.post('/webhooks/beds24', (req, res) => {
  const booking = req.body.booking;
  processNewBooking(booking);
  res.status(200).send('OK');
});
```

### Batch POST Requests

**Bad:**
```javascript
// ❌ 100 API calls
for (const booking of bookings) {
  await createBooking([booking]);
}
```

**Good:**
```javascript
// ✅ 1 API call
await createBooking(bookings);
```

### Batch GET Requests

**Bad:**
```javascript
// ❌ 5 API calls
const prop1 = await getProperties({ id: [1001] });
const prop2 = await getProperties({ id: [1002] });
const prop3 = await getProperties({ id: [1003] });
```

**Good:**
```javascript
// ✅ 1 API call
const properties = await getProperties({ id: [1001, 1002, 1003] });
```

### Monitor Rate Limits

```javascript
async function apiRequest(endpoint, options) {
  const response = await fetch(endpoint, options);
  
  const remaining = response.headers.get('X-FiveMinCreditLimit-Remaining');
  const resetIn = response.headers.get('X-FiveMinCreditLimit-ResetsIn');
  
  if (remaining < 10) {
    console.warn(`Low credits: ${remaining} remaining, resets in ${resetIn}s`);
    // Consider pausing requests
  }
  
  return response.json();
}
```

## FAQ

### How do I access API V2?
1. Generate invite code at https://beds24.com/control3.php?pagetype=apiv2
2. Exchange for refresh token: `GET /authentication/setup`
3. Get access token: `GET /authentication/token`
4. Include token in requests: `token: {access-token}`

Try it out: https://beds24.com/api/v2/

### What are scopes?
Scopes limit what your token can do. Set when creating invite code.

Example: `read:bookings` allows GET /bookings, but `write:bookings` is needed to POST.

### How long do tokens last?
- **Invite codes:** 24 hours
- **Refresh tokens:** Forever (if used within 30 days)
- **Long-life tokens:** Forever (if used within 90 days)
- **Access tokens:** 24 hours

### How big are tokens?
152-172 characters

### What is the API credit limit?
Dynamic limit in 5-minute rolling window. Cost varies by request complexity.

Check headers:
- `X-FiveMinCreditLimit` - Your limit
- `X-FiveMinCreditLimit-Remaining` - Credits left
- `X-FiveMinCreditLimit-ResetsIn` - Seconds until reset
- `X-RequestCost` - This request's cost

### Is the API limited per token or account?
**Account level.** All tokens under the same account share the same credit limit.

Sub-accounts have separate limits.

### How do I create a new booking/property/room?
Don't include `id` in POST request.

**Examples:**
- [Properties](https://beds24.com/api/v2/#/Properties/post_properties)
- [Bookings](https://beds24.com/api/v2/#/Bookings/post_bookings)

### Where can I see price rules?
`GET /properties?includePriceRules=true`

### Where can I see offers?
- **Setup rules:** `GET /properties?includeOffers=true`
- **Calculated prices:** `GET /inventory/rooms/offers?arrival=2025-11-15&departure=2025-11-20&numAdults=2`

### How do I set prices/availability for specific dates?
`GET /inventory/rooms/calendar` - Read calendar
`POST /inventory/rooms/calendar` - Update calendar

### How can I see if a date is available for check-in/out?
`GET /inventory/rooms/availability`

**Interpretation:**
- `true` - Check-in allowed
- `false` - Check-in NOT allowed
- If previous date is `true`, check-out is allowed

### What is the max POST request size?
- **Payload:** ~1MB
- **Array items:** 10,000 top-level items

### What does "coming soon", "alpha", or "beta" mean?

**Coming Soon:**
- Not developed yet
- Schema is indicative (may change)
- Not usable

**Alpha:**
- Usable but in development
- Not all features implemented
- Breaking changes unlikely but may occur

**Beta:**
- Mostly finished, being tested
- Most features implemented
- Breaking changes not planned
